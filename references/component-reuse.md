# 组件与框架能力复用

目的：减少模型间审美波动，把经过验证的布局、材质和运动能力当作可靠基底，再根据文案导演组合。复用的是表现能力，不是上一条片的固定顺序。

实拍剪辑、转写、AI素材、编码与高质量合成的能力入口见 [制作工具路由](production-toolkit.md)。它区分本例真正运行过的工具与其他候选，并说明何时应升级能力；不要把工具名等同于审美或完成度。

## 开工顺序

1. 先查看当前项目已有依赖、组件、设计token与成功镜头。已有能力能满足要求时直接复用并调整内容参数。
2. 缺失能力优先核对所选框架官方插件、示例与组件生态，评估能否接入主时间轴、适配画幅、替换素材和离线封装。
3. 仍有缺口时只编写薄适配层或具体镜头组合。独特语义隐喻确需自定义算法时再实现，并说明原因。
4. 登记选择依据、版本、来源、属性控制方、测试状态。没有实际下载/运行的候选组件不能标为可用。

## 能力候选表

下列均为能力入口，不表示本仓库已安装插件或附带成品组件。使用前核对版本、许可与依赖；来源链接以官方文档为准。

| 视觉需求 | 优先考察能力 | 接入注意 |
| --- | --- | --- |
| 卡片/人物窗布局间连续过渡 | [GSAP Flip](https://gsap.com/docs/v3/Plugins/Flip/) | 记录布局状态与目标；跳转时重建绝对状态，避免DOM布局副作用破坏回拖 |
| 连线/图表线条生长 | [GSAP DrawSVG](https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/) 或 [Anime.js SVG](https://animejs.com/documentation/svg/) | 二选一控制同一路径；主时钟寻址 |
| 路径与形状变换 | [GSAP MorphSVG](https://gsap.com/docs/v3/Plugins/MorphSVGPlugin/) 或 Anime.js SVG | 检查路径对应与中间形态，不把任意路径硬变形 |
| 分字/分行标题动画 | [GSAP SplitText](https://gsap.com/docs/v3/Plugins/SplitText/) | 字体加载、中文分词/换行、尺寸变化后重排；不要为每个字分配无意义随机运动 |
| 群组交错/计数/几何数值 | [Anime.js](https://animejs.com/documentation/) | 把动画结果与主时间关联，处理单位适配 |
| 粒子、环境、透视与材质 | [Three.js官方示例](https://threejs.org/examples/) | 按主题选具体示例后再登记；检查GPU成本、版本与依赖 |
| 毛玻璃、遮罩、渐变与排版 | 项目已有CSS/组件与浏览器原生能力 | 样式能力无需为了三维而三维；真实折射另选可证明的材质实现 |

不要因为上述插件存在就全部引入；只复用本片有实际作用且符合明确技术约束的能力。

## 复用组件的最小契约

按已有项目接口适配，至少能说明以下职责：

- 接受文案、素材ID、布局与视觉token，避免在组件内部写死场景内容。
- 可从绝对时间或局部进度设置状态，支持暂停、向前和向后定位。
- 明确自己拥有的动画属性；不与其他引擎争写。
- 能随画幅变化布局、替换素材，并释放动画/纹理/监听器。
- 把运动、裁切、材质等做成可调参数；导演通过参数和场景连接构建新叙事。

## 组件登记

本地实现或适配后的能力登记在 [组件目录](../components/catalog.md)。状态区分 `candidate` 候选、`integrated` 已接入、`verified` 已通过指定环境测试。只有能指出实际文件、接口和证据时，才写后两种状态。

## 复用验收

既检查来源复用，也检查叙事差异：是否少写了已有成熟实现？是否保留字体与材质一致性？去掉文案后，两条不同主题视频是否仍是完全相同的分页序列？如果是，应回到导演阶段调整镜头组合，而不是再加更多装饰。
