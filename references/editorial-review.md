# 观众可见内容与语义验收

成片是用户面向观众的作品。制作思考、技术标签、检查记录留在 brief、direction、implementation、report 或编辑控制器中；只有服务于本片主题的内容才进入画面、旁白、字幕和封面。

## 每段先过三项

1. **听到什么**：原句到底在说哪个对象、事件、观点？否定、比较、时间和因果是否保留？
2. **看到什么**：图和素材会让不看制作过程的观众推断出什么？是否与原句、已确认背景和证据一致？
3. **为什么在这里**：它在证明、解释、举例、烘托还是推进故事？删掉后若表达不损失、只剩“我会做特效”，通常应该简化或换掉。

AI插画可以承担比喻/情境，真实截图承担证据，示意图承担解释，角色承担讲述。角色不同不意味着可以互换。没有资料时，不画真实收益、后台通知、软件操作成功、身份和产品结构。标“概念”也不能修复主题错配。

## 成片文案表

在分镜或制作配置中列出所有新增可见文案：标题、章节、标签、角标、图表轴、AI素材内文字、封面、结尾和可听见的新增旁白。每项记录“原句/事实/用户既有品牌来源、观众用途、是否保留”。原稿字幕与编辑新增文案分开，不能用编辑观点替换原话。

| 常见问题 | 应如何处理 |
| --- | --- |
| 擅自给普通话题冠名“AI剪辑实测 / VISUAL LAB / EP.01” | 从本片选题与用户账号命名习惯提炼；系列名、集数未成立时不强加。若用户真实主题就是AI剪辑且认可命名，可以使用，不是字符串黑名单 |
| “画面焦点交给核心问题”“把复杂关系展开”“此处内容黑化”等导演自语 | 移到制作记录；若黑化是用户故事本身的情节，再按原意表达 |
| “素材提取完成”“已校验”“模型生成中”等生产日志 | 默认不进片。若教程确实讲这一步，可以展示真实操作和必要信息，不能插入助手的自言自语 |
| 讲一个具体经历，放通用玻璃设备/机器人/炫酷场景 | 回到上下文与素材请求；有明确比喻关系才采用，不能因“精美”就保留 |
| 把参考片数字、评论、弹幕、作者名、热度当内容 | 只学习构图机制；不移植成绩，不把平台叠层误当原片包装 |
| 把“超过98%的同类作者”写成“增长98%” | 回查证据口径；排名、增幅、转化率与绝对数量分别处理，不能因动效重绘改义 |

## 验收方式

- 按原句顺序对照画面，再关闭制作说明看一遍：陌生观众能否理解？画面是否引出未经原稿支持的结论？
- 列表核对最终导出中的全部新增文字和新增声音，不只查主字幕。可以自动提取文字辅助排查，但不能靠敏感词黑名单代替语义审阅。
- 关键证据先看原图，再看聚焦后的图；数字、单位、来源和日期不丢失，标题承诺在正文能兑现。
- 技术全解码、截图和音轨哈希是各自的证据，不冒充完整人工听辨、连续观看、运营效果或事实核验。
- 发现背景/主题不对，返工00需求；动效表达不对返工01/02；多余工程字返工04。输出报告诚实记录尚未验证项。
