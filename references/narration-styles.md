# 口播表达形态与混剪选择

这里选的是“怎样讲”，[视觉语言库](styles.md)选的是“看起来怎样”。先按受众、内容、用户习惯和现有素材选一个主形态，按段落借用其他形态；不按固定秒数或固定镜头数量拼模板。

| 表达形态 | 适合的内容 | 画面/声音组织 | 容易做坏的地方 |
| --- | --- | --- | --- |
| 干净人物口播 | 观点、经验、个人信任 | 人物和自然停顿主导，少量关键词与精简字幕 | 为显得会剪而铺满卡片、删除所有呼吸 |
| 人物＋证据讲解 | 复盘、增长、评测、案例 | 截图先给上下文，再裁切聚焦，数字从真实区域引出 | 将同行成绩变成用户成绩，重绘时改错口径 |
| 人物＋软件演示 | 工具教程、操作教学 | 人物建立联系后让位给录屏，局部推近指向实际点击与结果 | 假软件窗口、人物一直占主舞台、窗口里字不可读 |
| 白板/手绘推演 | 概念、因果、方法论 | 逐步写画，边说边连线/拆解，保持可回溯的推理结构 | 把全部文字一次铺满，手写动画与讲述顺序不一致 |
| 动态字/图形叙事 | 强观点、短解释、转折 | 重点词成为主体，形变表达替代/包含/对比，结论处放慢 | 每个字都乱跳、只有逐句标题卡 |
| 故事/B-roll混剪 | 经历、纪实、情感、过程 | 原声可跨镜头延续，照片/实拍/环境细节承担具体情境 | 用不相干图库片段，剪断因果和人物关系 |
| 角色/拼贴/梗图讲述 | 幽默科普、轻故事、匿名表达 | 稳定角色、表情反应、截图拼贴和有依据的包袱 | 把别人的角色当用户品牌，笑点压过事实，滥用热梗 |
| 产品/三维演示 | 结构、功能、设计、空间关系 | 真实模型/素材与镜头、灯光、材质配合，人物按需退出 | 用平面图片漂移冒充结构拆解、编造产品内部 |
| 访谈/对谈摘编 | 对话、采访、争议讨论 | 保留说话者归属、问答联系和反应镜头 | 拼接后让人表达相反观点，误把另一人台词配给当前人物 |

圆形小窗适合陪伴式讲解；圆角窗适合与录屏并置；全屏人物适合情绪和信任。它们都是叙事工具，不是“自媒体必须圆形”的规则。人物也可暂时完全退出，为证据、白板或实拍留场。

讨论候选时用内容说明差异：例如“这段重在证明结果，可以先给后台截图；解释原因的下一段改成白板推演”。不要只让用户在“高级/炫酷/科技风”中选择。
