# Lemo-Opuscar 对照研究与 Chinese baby 改进结论

研究日期：2026-10-31。研究对象为 [lemomo-ai/lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) 当日公开源码压缩包；本次阅读了 `AGENTS.md`、`DIRECTOR.md`、`TECHNIQUE.md`、Skill 入口、风格模板，以及 Dark Tech Keynote、Swiss Motion Graphics、Living Screencast、One-line Drawing 等风格文档和部分演示源码。没有把源码阅读写成已完整观看全部演示片。

## 它为什么比普通“视频提示词”稳定

| 维度 | Lemo-Opuscar 的机制 | Chinese baby 原有差距 | 本次改进 |
| --- | --- | --- | --- |
| 意图理解 | 主题、风格与用户材料一次问清；故事由当前主题决定 | 原则很多，但主任务、案例范围和用户纠正没有持续锁定 | 新增意图合同、决策顺序和纠正返工规则 |
| 创意结构 | 动笔前先给三个结构，选一个并说明理由；先写 treatment 再看 demo | 容易直接落入第一个视觉想法 | 导演模板加入三种候选结构、选择依据和开尾回响 |
| 风格约束 | 每种风格都有本质、禁区、材质、颜色、字体、运动、摄影机、声音、原生动作、陷阱和变化空间 | 五种视觉语言偏描述性，模型仍能随意解释 | 新增十二项风格合同，并要求分镜与验收引用 |
| 镜头衔接 | 转场来自媒介本身；镜头列景别、角度、摄影机运动、时长和原因 | 有对象继承，但缺少稳定的摄影机/转场语法 | 分镜增加景别、摄影机、声音、入场与交棒状态 |
| 节奏与声音 | 同一时间源驱动画面、音乐、音效、字幕与检查；有 cue map、J/L cut、静默 | 只要求同一项目时间，没强制节拍和声音设计 | 制作与分镜加入共享时间线、节拍点和声音交接 |
| 验收 | 联系表、关键动作 0.2 秒帧条、全速带声观看、读时和卡点检查 | 技术验证较强，动态表演与听感证据不足 | 加入三类动态验收和“长镜头持续变化”检查 |
| 能力复用 | 风格文档同时指向可复用引擎与明确函数，示例工程可重建 | 组件目录几乎为空，指南多于实现 | 明确“代表镜头先验证”和组件登记；后续需继续积累可运行组件 |

## 最值得学习的镜头方法

Dark Tech Keynote 的镜头变化不是换页面：局部 UI 从来源位置扩成全屏，下一镜再收回原对象；数字镜头通过推入状态栏计数器完成匹配切换。Living Screencast 把整支片放在连续的软件空间里，摄影机沿真实界面锚点移动，章节转场才允许切换。One-line Drawing 让一条线跨章节持续存在，连接本身就是镜头交棒。它们共同解决的是空间连续性，而不只是缓动曲线。

## 仍不能直接照搬的部分

- Lemo-Opuscar 主要面向代码生成短片；Chinese baby 还需处理真人口播、用户素材、真实录屏、补拍和传统剪辑。
- 风格数量不会自动带来理解力。若意图合同错误，六十六种风格只会更快地产生错误方向。
- 它明确针对 Claude Opus 调优；Chinese baby 应把关键判断写成模型无关的产物和检查点，并用真实任务回归。
- 引入外部模板时需保留来源和许可；用户私有素材继续留在具体项目，不进入开源 Skill。

## 后续能力债务

文档约束已经补强，但可运行组件仍是明显短板。下一阶段应围绕最常用的连续摄影机、媒介内转场、逐词时间轴、字幕读时检查、卡点检查和声音事件表，逐个做成可验证组件；每个组件先通过一支短样片，再登记为可复用能力。
